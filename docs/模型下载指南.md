# 模型下载指南（中国大陆网络友好）

记录本项目用到的模型下载方案，重点是**在国内网络环境下怎么快速、稳定地拿到模型**，
避免 HuggingFace 直连慢、代理假 IP 冲突、下载中断留下残片这些坑。

> 所有命令与速度均为**本机实测**（Apple Silicon Mac，未挂代理直连国内镜像时约 15 MB/s；
> HuggingFace 直连约 170 KB/s；走 ClashX 代理约 200 KB/s）。

---

## 一、mlx-whisper 模型下载

语音转文字依赖 `mlx_whisper`，模型默认从 HuggingFace 拉取。国内直连很慢，
推荐用国内镜像下载到**本地目录**，再让 `.env` 指向它，一劳永逸。

### 方式 1：ModelScope 魔搭镜像（推荐，实测最快）

ModelScope 是国内阿里的模型托管平台，同步了 `mlx-community` 的模型，直连速度约 **15 MB/s**。
`whisper-large-v3-turbo`（1.5GB）约 100 秒就能下完。

```bash
# 1) 下载到本地目录
mkdir -p ~/models/whisper-large-v3-turbo-mlx
curl -L --noproxy '*' --retry 5 --retry-delay 3 -C - \
  -o ~/models/whisper-large-v3-turbo-mlx/weights.safetensors \
  "https://modelscope.cn/models/mlx-community/whisper-large-v3-turbo/resolve/master/weights.safetensors"
curl -L --noproxy '*' \
  -o ~/models/whisper-large-v3-turbo-mlx/config.json \
  "https://modelscope.cn/models/mlx-community/whisper-large-v3-turbo/resolve/master/config.json"

# 2) .env 里指向本地目录（不再联网）
# WHISPER_MODEL=/Users/<你>/models/whisper-large-v3-turbo-mlx
```

> `--noproxy '*'` 表示不走代理直连（ModelScope 国内访问快，走代理反而可能绕慢）。
> `-C -` 是断点续传，中断了重跑同一条命令即可接着下。

各模型在 ModelScope 上的路径与体积（**均已实测存在**）：

| 模型 | 权重文件 | 体积 | 中文识别 |
| --- | --- | --- | --- |
| `mlx-community/whisper-tiny-mlx` | `weights.npz` | 71 MB | 差（不推荐正式用） |
| `mlx-community/whisper-base-mlx` | `weights.npz` | 137 MB | 一般 |
| `mlx-community/whisper-small-mlx` | `weights.npz` | 459 MB | 较好（推荐折中） |
| `mlx-community/whisper-large-v3-turbo` | `weights.safetensors` | 1539 MB | 最好（默认） |

替换 URL 里的模型名和文件名即可下载其它规格：

```bash
# 例：下载 small（459MB，约 30 秒）
curl -L --noproxy '*' -C - -o ~/models/whisper-small-mlx/weights.npz \
  "https://modelscope.cn/models/mlx-community/whisper-small-mlx/resolve/master/weights.npz"
```

### 方式 2：hf-mirror 镜像

如果更习惯 HuggingFace 的仓库名，用 `hf-mirror.com` 做端点镜像即可（支持断点续传）：

```bash
export HF_ENDPOINT=https://hf-mirror.com
huggingface-cli download mlx-community/whisper-large-v3-turbo --local-dir ~/models/whisper-large-v3-turbo-mlx
```

> 说明：hf-mirror 的大文件会重定向回 HuggingFace 的 AWS CDN，实测速度不一定比 ModelScope 快，
> 但作为「习惯用 HF 仓库名」的替代方案是可行的。**优先用方式 1**。

### 方式 3：HuggingFace 直连（慢，仅兜底）

不推荐，仅在没有镜像可用时兜底。实测约 170 KB/s，`large-v3-turbo` 要 2.5 小时以上，
中途很容易断。若必须直连，记得用 `npm run stt:download`（自带断点续传，不受转写超时限制）。

## 二、本地模型目录（推荐配置方式）

`WHISPER_MODEL` 现在支持**两种写法**：

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| HuggingFace 仓库名 | 去 HF 缓存/镜像找，首次自动下载 | `mlx-community/whisper-large-v3-turbo` |
| 本地目录 | 直接用该目录下的权重，**不再联网** | `/Users/you/models/whisper-large-v3-turbo-mlx` |

判断规则：以 `/`、`~`、`./`、`../` 开头都会按「本地目录」处理，其余按 HF 仓库名处理。

本地目录下只需有 `config.json` + 权重文件（`weights.npz` 或 `weights.safetensors`）即可：

```bash
~/models/whisper-large-v3-turbo-mlx/
├── config.json
└── weights.safetensors
```

配合方式 1 下载后，`.env` 里写：

```ini
WHISPER_MODEL=/Users/you/models/whisper-large-v3-turbo-mlx
```

改完重启服务，`curl localhost:3210/api/audio/status` 应显示 `modelCached: true`。

## 三、ollama 模型下载（含 ClashX 假 IP 冲突）

「生成描述」走 ollama（默认 `qwen3:4b`），正常 `ollama pull` 即可。但如果**开着 ClashX / Clash Verge
等代理的 fake-IP 模式**，会碰到一个典型错误：

```
Error: max retries exceeded: redirect target not allowed:
dd20bb891979...r2.cloudflarestorage.com resolves to non-public 198.18.16.92
```

### 原因

Clash 的 fake-IP 模式把所有域名都解析成 `198.18.x.x`（保留网段）。ollama 的 Go 客户端在跟随下载
重定向（跳转到 Cloudflare R2 存储）时会自己做 DNS 校验，拒绝这个「非公网 IP」，于是拉取失败。
这是 ollama 0.35+ 的 SSRF 防护和 Clash fake-IP 的冲突，与模型本身无关。

### 解决办法（任选其一）

1. **关掉代理的 fake-IP 模式**（ClashX 里改成「增强模式/TUN」或临时退出代理），再 `ollama pull` —— 最省事。
2. **升级 ollama**：旧版本（如 0.40.2）某些模型要求更高版本（如 `lfm3-audio` 标注 `requires: 0.40.13`）。
3. **手动下载 blob**（见下，网络实在不行时的兜底）。

### 手动下载 blob（兜底方案）

ollama 的模型 = 若干 blob 文件 + 一个 manifest。可以手动把 blob 下到本地目录绕开其下载器：

```bash
# 1) 拿 manifest（注意 Accept 头必须带 manifest.v2，且要跟重定向 -L）
curl -sL "https://registry.ollama.ai/v2/library/<模型名>/manifests/<tag>" \
  -H "Accept: application/vnd.docker.distribution.manifest.v2+json" \
  -o /tmp/model-manifest.json

# 2) 按 manifest 里每个 layer 的 digest 下载 blob 到 ~/.ollama/models/blobs/
#    digest 形如 sha256:xxxx，文件命名规则：sha256-<hex>
curl -fsSL --retry 5 -C - \
  -o ~/.ollama/models/blobs/sha256-<hex> \
  "https://registry.ollama.ai/v2/library/<模型名>/blobs/sha256:<hex>"

# 3) 把 manifest 复制到 models/manifests 对应路径
mkdir -p ~/.ollama/models/manifests/registry.ollama.ai/library/<模型名>
cp /tmp/model-manifest.json ~/.ollama/models/manifests/registry.ollama.ai/library/<模型名>/<tag>

# 4) 验证
ollama list   # 应能看到该模型
```

**关键坑（实测）**：某些模型（如 `lfm3-audio`）的投影层 `mmproj-*.gguf` 是 ollama **二次处理过的**
（blob digest 与 HF / ModelScope 上的原版 mmproj 不同，虽然文件大小一样）。所以这类 blob
**只能从 ollama 的 registry 下载**，不能用 HF / ModelScope 的原版 mmproj 顶替；主权重 GGUF 则完全一致，
可以用 ModelScope 加速（`LiquidAI/LFM3-Audio-2B-GGUF` 等仓库）。

## 四、下载中断的残片清理

下载中断会留下 `.incomplete` 残片（可能好几个 GB），还会让 `modelCached` 误判模型不可用。

```bash
# 看状态
curl -s localhost:3210/api/audio/status | grep -o '"incompleteCount":[0-9]*'

# 只删残片（不动完整权重）
npm run clean -- --model-cache --yes
```

whisper 的残片位于 `~/.cache/huggingface/hub/models--<模型名>/blobs/*.incomplete`，
也可手动 `rm`。

## 五、故障排查速查表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 转写报 503「模型尚未下载完成」 | 模型没下完 / 配置指向错误 | 见「方式 1」用 ModelScope 下到本地目录，`.env` 指向它 |
| 下载速度 ~170 KB/s | HuggingFace 直连 | 换 ModelScope 镜像（方式 1） |
| `redirect target not allowed` | Clash fake-IP 与 ollama 冲突 | 关 fake-IP 或手动下载 blob（第三节） |
| `.incomplete` 残片很多 | 下载反复中断 | `npm run clean -- --model-cache --yes` 后重新下 |
| 模型下载成功但仍 503 | 权重不完整（0 字节） | 检查本地目录里 `weights.*` 是否非空 |
| 换模型后仍报旧模型名 | `.env` 没生效 | 重启服务（改 `.env` 必须重启） |
